# neumAC R&I — Consolidation Phase 2

## Purpose
Phase 2 removes presentation ownership from HTML and API-generated markup while preserving the current site structure and behaviour. It is a consolidation pass, not a visual redesign.

## What changed

- Removed literal `style="..."` attributes from every HTML page.
- Removed literal `style="..."` attributes from markup generated by `api.js`.
- Replaced those declarations with named component/page classes.
- Consolidated repeated footer, legal-page, cookie-banner, icon, contact and form presentation into `styles/components.css`.
- Moved page-specific presentation into the relevant `styles/pages/*.css` owner.
- Replaced dynamic style interpolation in generated content with state/modifier classes (for example line facts, trials, publications, avatar fallbacks and loading skeletons).
- Retired CSS selectors that depended on matching inline style text (`[style*=...]`).
- Replaced the old inline-style contrast patch with explicit semantic component targets.
- Extended `scripts/integrity_check.py` so inline style attributes and style-attribute CSS selectors now fail CI/local integrity checks.

## Measured debt removed

Phase 1 baseline:

- 459 literal `style=` occurrences in HTML pages.
- 119 literal `style=` occurrences in root JavaScript-generated markup.
- 25 CSS selectors coupled to style attributes (`[style...]`).

Phase 2 baseline:

- 0 literal `style=` occurrences in HTML pages.
- 0 literal `style=` occurrences in root JavaScript-generated markup.
- 0 CSS style-attribute selectors.

That is 578 literal inline presentation declarations removed from markup/templates.

## Deliberately unchanged

- No visual redesign was attempted.
- Public API endpoints/contracts were not changed.
- Supabase/backend behaviour was not changed.
- Bilingual EN/ES logic was not changed.
- Imperative `element.style...` assignments used for runtime state, visibility, animation or measured canvas behaviour remain where they are behavioural rather than markup presentation. These can be rationalised during the behaviour/component consolidation phase.

## Validation

- All HTML div-balance checks pass.
- All HTML parser checks pass.
- No embedded `<style>` blocks.
- No `core.css` / `polish.css` references.
- No literal inline style attributes in HTML.
- No literal inline style attributes in JavaScript-generated markup.
- No CSS `[style...]` selectors.

- `tokens.css` remains the only `:root` token source.
- `--ink-4` contrast regression guard still passes at 4.54:1 on white.

- Static HTTP checks return 200 for core pages and canonical stylesheets.

# Research Line Scientific Identity — R1.2 Scientific Leadership System

## Status

Architecture specification only. No production HTML, CSS or JS changes.

## Governing principle

> **The coordinator is evidence of the line’s scientific leadership, not the destination.**

The research line remains the primary subject. Leadership information exists to establish scientific credibility, governance and context without turning the page into a staff profile or CV.

---

## 1. Main-page leadership preview

The research-line page keeps one restrained **Scientific leadership / Liderazgo científico** section.

Required content:
- approved portrait or initials;
- full name;
- line role;
- specialty / professional context;
- concise public bio tied to the line.

Maximum three preview evidence signals:
1. **Scientific leadership & contribution**
2. **Recognition**
3. **Networks & societies**

These signals are concise summaries, not full lists.

The preview must remain visually subordinate to:
- the line hero;
- scientific scope;
- current activity;
- portfolio and evidence.

---

## 2. Trajectory action

A subtle action such as:

**Scientific trajectory → / Trayectoria científica →**

opens a contextual leadership sheet.

It does not navigate to a separate full-page person profile.

Desktop target:
- approximately 35–40% viewport width;
- line page remains visible beneath/alongside;
- no stronger visual hierarchy than the line hero;
- normal document context is preserved.

Tablet/phone:
- sheet may become a bottom sheet or full-height overlay for usability;
- the content hierarchy remains identical;
- closing returns the user to the same line-page state.

---

## 3. Allowed drawer modules

Only approved modules with content render.

### A. Scientific leadership & contribution

Combines leadership and scientific contribution in one module.

Examples:
- coordination of the research line;
- leadership of clinical or multicentre studies;
- guideline/consensus contribution;
- clinically relevant research programmes;
- translational or innovation leadership;
- selected high-signal scholarly contributions.

Maximum recommended public items: 3–5.

### B. Recognition

Optional.

Examples:
- recognised professional lists;
- awards;
- fellowships;
- invited distinctions;
- relevant institutional honours.

Recognition must be:
- sourceable;
- approved for publication;
- stated factually;
- never styled as a promotional badge wall.

### C. Networks & societies

Optional.

Examples:
- scientific-society roles;
- working groups;
- registries;
- multicentre networks;
- consortia;
- guideline groups.

Only current or scientifically relevant roles should be shown.

### D. Scientific identity

Functional external identity.

Possible links:
- ORCID;
- Google Scholar;
- PubMed author search/profile;
- institutional profile;
- Web of Science / ResearcherID where appropriate.

The system must tolerate only one available link.

### E. Research footprint

A compact visual evidence band.

Potential metrics:
- publications;
- citations;
- h-index.

Rules:
- source must be known;
- values must include a verified/updated date in data;
- no invented or estimated values;
- metrics may be omitted entirely;
- metrics are contextual evidence, not competitive ranking.

---

## 4. Explicit exclusions

R1.2 does **not** introduce:
- a separate full professional-profile page;
- “Professional focus” as a drawer module;
- a generic “Selected milestones” block;
- duplicated biography content;
- long chronological CVs;
- education history unless materially relevant;
- decorative prestige badges;
- scores or rankings generated by neumACt;
- inferred achievements.

Professional focus remains implicit in the line context and concise bio.

Milestones belong under the relevant evidence type, primarily Scientific leadership & contribution or Recognition.

---

## 5. Sparse and rich states

### Sparse state

Minimum content:
- name;
- role;
- specialty/context;
- short approved bio.

The drawer action may be hidden when there is no additional approved evidence.

No empty module shells are shown.

### Moderate state

May show:
- leadership & contribution;
- one network/society module;
- one or more scientific identity links.

### Rich state

May additionally show:
- recognition;
- research footprint;
- multiple approved network roles.

**Richness changes depth, not hierarchy.**

The research line remains primary in every state.

## 6. Data contract

The public API should eventually expose a governed additive object such as:

```json
{
  "scientific_leadership": {
    "short_bio": {"en": "", "es": ""},
    "evidence": [],
    "scholarly_identity": [],
    "research_footprint": null
  }
}
```

Evidence item:

```json
{
  "id": "uuid",
  "type": "scientific_leadership",
  "title": {"en": "", "es": ""},
  "description": {"en": "", "es": ""},
  "organisation": "",
  "year": null,
  "source_url": "",
  "source_label": "",
  "visibility": "approved_public",
  "verified_at": "",
  "person_approval": "approved",
  "display_priority": 50
}
```

Allowed evidence types for R1.2:
- `scientific_leadership`;
- `clinical_leadership`;
- `guideline`;
- `consensus`;
- `recognition`;
- `award`;
- `society_role`;
- `network_role`;
- `registry_role`;
- `programme_milestone`.

---

## 7. Research-footprint contract

Suggested structure:

```json
{
  "research_footprint": {
    "publications": 78,
    "citations": 4320,
    "h_index": 25,
    "source": "approved source",
    "source_url": "",
    "verified_at": "2026-10-02"
  }
}
```

The UI must not show a metric if its provenance or freshness is unknown.

---

## 8. Editorial governance

The internal editorial system owns:
- evidence authoring;
- sources;
- visibility;
- bilingual copy;
- approval;
- display priority;
- review dates.

The public site owns only:
- filtering approved items;
- rendering;
- responsive behavior;
- accessibility;
- graceful empty states.

The internal editorial assistant may propose or flag content, but may not publish automatically.

---

## 9. Regression boundaries

R1.2 implementation must preserve:
- line hero;
- line-page section order;
- current activity metrics;
- studies/projects/publications data sources;
- masthead and Index/Search;
- responsive composition contract;
- global footer;
- current line failure states.

No coordinator content may cause horizontal overflow or force the line page into a person-centric composition.

---

## 10. R1.2 acceptance criteria

R1.2 is successful when:
- the line remains visually dominant;
- the leadership preview is understandable without opening the drawer;
- the drawer adds depth without becoming a CV;
- rich and sparse states both look intentional;
- only approved evidence renders;
- identity links and research-footprint data are provenance-aware;
- no person-specific biography remains hard-coded as the long-term content model.
